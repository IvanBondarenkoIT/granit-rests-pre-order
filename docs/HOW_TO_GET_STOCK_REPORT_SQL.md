# Как получить SQL отчёта «Остаток товара» без опыта в FastReport

**Коротко:** для работы приложения SQL отчёта **не обязателен**. Мы уже сверили остатки с леджером `SUM(GDDKT.QUANT)`; расхождение по Cleaning ~3% объясняется последними документами перемещения (см. [`STOCK_CALIBRATION_FINDINGS.md`](STOCK_CALIBRATION_FINDINGS.md)).

SQL из отчёта нужен только если хотите **100% совпадение** с печатной формой Granit.

---

## Вариант 1 — через клиент Granit (если есть права)

1. Откройте тот же отчёт: **«Остаток товара (по доступным группам)»**.
2. В окне предпросмотра или в меню отчёта ищите:
   - **«Дизайнер»** / **«Designer»**
   - **«Изменить»** / **«Редактировать отчёт»**
   - иконку карандаша / шестерёнки рядом с отчётом
3. Если пункт **неактивен** — у вашего пользователя нет прав на редактирование форм. Нужен администратор Granit или учётка с правами на отчёты.

В Дизайнере:
- двойной клик по объекту **«Данные»** / **Query** / **MasterData**
- вкладка **SQL** или **Запрос** — скопировать текст

---

## Вариант 2 — попросить администратора (самый простой)

Попросите IT / админа Granit **одно из**:

| Что попросить | Зачем |
|---------------|--------|
| Текст SQL из отчёта «Остаток товара (по доступным группам)» | Сразу в проект |
| Файл шаблона `.fr3` этого отчёта | Можно разобрать утилитой |
| Экспорт строки из таблицы `FRREPORT` для этого отчёта | Шаблон лежит в БД |

Формулировка для админа:

> Нужен SQL-запрос или файл `.fr3` отчёта FastReport «Остаток товара (по доступным группам)» для сверки остатков с внешним приложением.

---

## Вариант 3 — извлечь из базы Firebird (у нас в проекте)

В Granit шаблоны FastReport хранятся в таблице **`FRREPORT`** (поле `TEMPLATE` — BLOB).

В **локальной копии** `GEORGIA.GDB` сейчас только **5** отчётов (накладные, КП) — **отчёта об остатках там нет**. Вероятно, полный набор форм на **боевом сервере** или в другой выгрузке.

Утилита проекта:

```powershell
$env:PYTHONPATH="."
.\.venv\Scripts\python.exe tools\stock_extract_frreport.py --list
.\.venv\Scripts\python.exe tools\stock_extract_frreport.py --search остат
.\.venv\Scripts\python.exe tools\stock_extract_frreport.py --id <ID> --out data/frreport/
```

Если админ даст **свежую .GDB с сервера** или выгрузку `FRREPORT` — запустите `--search остат` / `GDDKT`.

## Вариант 4 — файлы Granit в проекте (готово)

Копия ERP лежит в **`data/input/GRANIT/`**. Отчёты склада — в **`FrfStor/`** (формат **`.frf`**, не только `.fr3`).

Целевой шаблон:

`data/input/GRANIT/FrfStor/Наличие товара/Остаток товара (по доступным группам).frf`

SQL зафиксирован в [`STOCK_REPORT_SQL.md`](STOCK_REPORT_SQL.md). FastReport Designer **не нужен**.

```powershell
$env:PYTHONPATH="."
.\.venv\Scripts\python.exe tools/stock_scan_granit_fr3.py --search остат
.\.venv\Scripts\python.exe tools/stock_scan_granit_fr3.py --extract "по доступным группам"
```

Инвентарь каталогов: [`DATA_INPUT_INVENTORY.md`](DATA_INPUT_INVENTORY.md).

## Вариант 5 — продолжить без SQL (рекомендуется сейчас)

| Группа | Точность `SUM(GDDKT.QUANT)` |
|--------|----------------------------|
| Coffee 250 g (Java, Columbia, Rosso) | ≤ 1 шт |
| DLSC550 | +1 шт |
| DLSC002, DLSC500 | +34 / +49 шт (~3%) |

Для **заказов и KPI** этого достаточно. Канон в [`DB_SCHEMA.md`](DB_SCHEMA.md): остаток = леджер GDDKT.
