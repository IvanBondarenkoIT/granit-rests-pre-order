## Раздел D. Поправка на дефицит (censored demand / «заниженный спрос»)

> **Зачем этот раздел:** когда товар **заканчивается**, в чеках видно **мало или ноль продаж** — но это не значит, что спрос упал: люди **не смогли купить**. Если строить прогноз только по продажам, система **недооценит** расход и **опоздает с заказом**.

### Пример (простыми словами)
- Июль: фильтров DLSC002 много → продаётся **50 шт/нед**.
- Август: остаток **0** три недели → в базе **0 продаж** (товара не было).
- Сентябрь: привезли партию → снова **45 шт/нед**.

**Наивный прогноз** по продажам увидит «провал в августе» и скажет: «расход падает, заказ не срочный».  
**Правильный подход (censored demand):** в недели дефицита заменить наблюдаемые 0 на **ожидаемый спрос** (например, как в те же недели прошлого года, когда товара хватало).

### Что нужно для этого в данных
Сейчас у нас есть:
- **продажи** по неделям (`weekly_sales`) — что реально продали;
- **остаток на конец недели** из леджера `GDDKT` (`weekly_stock`) — но это **текущий** нарастающий остаток, а не точный «остаток на каждую прошлую дату» без реконструкции.

Чтобы **надёжно** помечать недели дефицита и восстанавливать спрос, нужен **исторический on-hand по неделям**: «сколько было на складе в конце каждой недели в прошлом». Его можно:
- восстановить из движений (приходы минус продажи/списания), если типы документов согласованы; или
- взять из отчётов Granit, если есть снимки остатков.

**Пока этого нет** — в ETL `true_demand = observed_sales` (без «додумывания»). Включим unconstraining после появления достоверного исторического on-hand.

## Свободные заметки

- Валюта: **GEL (₾)**; закупка из `GDDKT.PRICE` **как есть, без добавления НДС**.
- Coffee (кг): параметр «Продукция» = «Кофе(кг)» (`FIXVAL=3`, ~96 SKU).
- Ориентиры в списке (300, 500…) = типичный объём **последнего заказа**.
- DLSC500 = ID **22284**, `AS00006183`.
- **Bag paper:** отдают бесплатно, продажи не отражают расход. План: оценивать расход по **графику приходов** (период между заказами ÷ объём партии → удельный расход/нед) или дефолт из ориентира 300 шт / типичный интервал заказа.
