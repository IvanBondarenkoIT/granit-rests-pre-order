# Схема БД (Firebird, GEORGIA.GDB) — релевантные таблицы

Версия: Firebird 2.5 (ODS 11). Чтение — embedded (`tools/fb25/fbembed.dll`), read-only.

## Товары
### GOODS — карточка товара
| Поле | Назначение |
|------|------------|
| `ID` | PK товара |
| `NAME` | наименование |
| `CODE`, `BARCODE` | артикул / штрих-код |
| `OWNER` | группа (FK → `GOODSGROUPS.ID`) |
| `SQNT` | **страховой запас** (карточка «Страх.остаток …») |
| `ONE`, `ONEID` | единица измерения |
| `NW` | вес нетто, кг |

### GOODSGROUPS — группы товаров
`ID`, `NAME`, `PARENTID` (иерархия). Агрегаты Coffee/Caotina = сумма `GOODS` по `OWNER`.

## Остатки / движения
### GDDKT — строки движения товара (в этой БД для критич. товаров — приходы)
| Поле | Назначение |
|------|------------|
| `GDSKEY` | товар (FK → `GOODS.ID`) |
| `DGVKEY` | шапка документа (FK → `DGVKT.ID`) |
| `QUANT` | количество движения (знаковое; здесь наблюдаются только приходы +) |
| `PRICE` | цена движения |

**Остаток** = нарастающая сумма `GDDKT.QUANT` по дате шапки `DGVKT.DAT_`
(проверено соседним проектом: точность ~99.76% к Excel).

### DGVKT — шапка документа движения
| Поле | Назначение |
|------|------------|
| `ID` | PK |
| `DAT_` | **дата документа/движения** |
| `TYP` | тип документа |
| `STORID` | склад |
| `CSDTKTHBID` | тип операции |
| `COMMENT` | комментарий |

## Продажи (сигнал спроса/расхода)
### STORZAKAZDT — шапка заказа/чека
`ID`, `DAT_` (дата), `SUMMA`, `CSDTKTHBID` (тип; продажи = `1,2,3,5`), `CREATEDATETIME`, `comment`.
**Отбор:** все точки продажи (без фильтра `STORGRPID`).

### STORZDTGDS — строки чека
`SZID` (FK → `STORZAKAZDT.ID`), `GODSID` (FK → `GOODS.ID`), `RSQUANT`, `SOURCE`, `PRICE`.
Количество продажи: `COALESCE(NULLIF(RSQUANT,0), SOURCE, 0)`.
`PRICE` здесь — **розничная** цена; для суммы заказа поставщику не используем.

## Параметры товара (классификация)
### GDSPARAMPRM / GDSPARAMVAL / GDSPARAMGDSREF
| Сущность | Назначение |
|----------|------------|
| `GDSPARAMPRM` | Справочник параметров (`ID=2` → «Продукция») |
| `GDSPARAMVAL` | Значения (`ID=3` → «Кофе(кг)») |
| `GDSPARAMGDSREF` | Привязка товара: `GOODSID`, `PARAMID`, `FIXVAL` → VAL.ID |

**Кофе в кг:** `GDSPARAMGDSREF.PARAMID=2` AND `FIXVAL=3` (~96 SKU).

## Правила домена (зафиксировано)
- **Остаток** = `SUM(GDDKT.QUANT)` **по всей компании** (все склады); межскладские перемещения не выделяем.
- **Спрос** = продажи `STORZAKAZDT` (все точки).
- **Страховой запас** = `GOODS.SQNT` (карточка).
- **Ориентир в списке критических товаров** (`target_qty`) = типичная **партия последнего заказа**, не SQNT.
- **Валюта закупки** = грузинский **лари (GEL, ₾)**; закупочная цена из приходов `GDDKT.PRICE` (средневзвешенная), **как в БД, без добавления НДС**.

## Важная находка (сигнал спроса)
Для критических товаров `GDDKT.QUANT` содержит **только приходы** (расход не пишется
отрицательными движениями), а реальное потребление видно в `STORZAKAZDT`. Поэтому:
- остаток для графика берём из леджера `GDDKT` (то, что показывают отчёты);
- расход/спрос — из продаж `STORZAKAZDT`;
- прогноз исчерпания: текущий остаток `GDDKT` расходуется по темпу продаж.

Эталон: `DLSC002` (`GOODS.ID=24227`), `SQNT=300`, остаток леджера 1139, расход ~37/нед.
